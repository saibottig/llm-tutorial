Ein Modell liest weder Buchstaben noch Wörter, sondern **Token**: Zahlen aus einem festen Vokabular von 100.000–200.000 Einträgen. Alles in einer Claude-Code-Sitzung — CLAUDE.md, Java-Klassen, Stacktraces, Jira-Tickets — wird in Token gemessen, gezählt und abgerechnet.

Grobe Anhaltspunkte:

| Text | Tokenverbrauch |
| --- | --- |
| häufiges kurzes Wort (`Fenster`) | 1 Token |
| langes Kompositum (`Rechtsschutzversicherung`) | mehrere Token |
| Englisch | ~5 Zeichen pro Token |
| Deutsch | ~15 % mehr Token als Englisch |
| Code, Logs, JSON | deutlich mehr als Fließtext gleicher Länge |

## Der Tokenizer gehört zum Modell

Derselbe Text ergibt bei demselben Modell immer exakt dieselbe Tokenfolge — egal wo es läuft oder wer es betreibt.

<Callout type="korrektur">
„Die Tokenzahl hängt vom Server ab" — nein. Die Tokenisierung ist Teil des Modells und fix. Vom Betreiber abhängt die **nutzbare Kontextlänge**: ein Modell kann technisch 1M Token können, aber auf 200k begrenzt betrieben werden.

Auch veraltet: „Deutsch kostet 2–3×". Das galt für ältere Tokenizer. Gemessen mit aktuellen: **+16 %** (`o200k_base`) statt **+53 %** (`cl100k_base`).
</Callout>

## Praktische Regeln

- **Messen statt schätzen.** Anbieter haben Zähl-Endpunkte; in Claude Code zeigt `/context` den Verbrauch der Sitzung.
- **Nie mit fremdem Tokenizer schätzen** (z. B. `tiktoken` für ein Nicht-OpenAI-Modell): je nach Inhalt zweistellig daneben, am stärksten bei Code und Nicht-Englisch.
- **Abrechnung, Grenzen, Geschwindigkeit** — alles wird in Token gemessen: Preise pro Token (Ein-/Ausgabe getrennt), Context Window in Token, Durchsatz in Token/s.

<Deep title="Warum Modelle Buchstaben nicht zählen können">
Ein Token ist keine Bedeutungseinheit — die Zerlegung folgt der Statistik des Trainingskorpus, nicht der Grammatik:

- Ein Leerzeichen gehört meist zum **folgenden** Wort: `" Fenster"` und `"Fenster"` am Satzanfang sind verschiedene Token.
- Dieselbe Buchstabenfolge kann je nach Umgebung unterschiedlich zerlegt werden.
- Zahlen werden in Stücke zerhackt — ein Grund, warum Modelle beim Rechnen stolpern.

Das Modell sieht nie einzelne Buchstaben, nur Token-Brocken. Deshalb scheitert es am Buchstabenzählen — es zählt in einer Einheit, die es nicht sehen kann.
</Deep>

<KeyTakeaway>
- Ein Token ist die kleinste Einheit, in der ein Modell Text wahrnimmt — alles wird darin gemessen und bezahlt.
- Der Tokenizer ist Teil des Modells und fix; der Betreiber bestimmt nur die nutzbare Kontextlänge.
- Deutsch kostet heute ~15 % mehr als Englisch, nicht 2–3× — die alte Regel stammt von älteren Tokenizern.
- Messen statt rechnen, nie mit dem Tokenizer eines anderen Modells.
</KeyTakeaway>
