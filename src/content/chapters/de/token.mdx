Ein Sprachmodell liest keine Buchstaben und keine Wörter. Es liest **Token**. Das ist die kleinste Einheit, in der Text für das Modell überhaupt existiert: eine Zahl aus einem festen Vokabular, das typischerweise 100.000 bis 200.000 Einträge umfasst.

Ein Token entspricht meist einem kurzen Wort, einer Silbe, einer Endung oder einem Satzzeichen. Häufige Wörter bekommen ein eigenes Token, seltene werden in mehrere Stücke zerlegt. Deshalb ist `Fenster` ein Token, `Rechtsschutzversicherung` aber mehrere.

## Wer bestimmt, wie zerlegt wird

Die Zerlegung übernimmt der **Tokenizer**, und der gehört fest zum Modell. Er wird zusammen mit dem Modell trainiert und ausgeliefert. Derselbe Text ergibt bei demselben Modell immer exakt dieselbe Tokenfolge — egal, wo das Modell läuft, wer es betreibt oder wie viel Speicher die Maschine hat.

<Callout type="korrektur">
Man liest oft, die Tokenzahl hänge vom Server ab, auf dem das Modell läuft. Das stimmt nicht. Die Tokenisierung ist Teil des Modells und liegt fest.

Vom Betreiber abhängt etwas anderes: die **nutzbare Kontextlänge**. Ein Modell mag technisch eine Million Token verarbeiten können — wenn der Anbieter nur so viel Speicher bereitstellt, dass 200.000 hineinpassen, ist bei 200.000 Schluss. Das ist eine Betriebsentscheidung, keine Eigenschaft des Modells. Mehr dazu im Kapitel [VRAM und RAM](../vram-vs-ram/).
</Callout>

## Die Faustregel und ihr Verfallsdatum

Die verbreitetste Regel lautet: ein Token sind ungefähr vier Zeichen. Für Englisch liegt sie mit aktuellen Modellen eher bei fünf. Für Deutsch hört man dagegen oft, es seien nur zwei bis drei — Deutsch sei durch seine Komposita deutlich teurer.

Das war einmal richtig und ist es heute so nicht mehr. Ältere Tokenizer waren stark auf Englisch optimiert; deutscher Text kostete real gut 50 Prozent mehr Token als derselbe Inhalt auf Englisch. Aktuelle Tokenizer haben diese Lücke weitgehend geschlossen — übrig bleibt ein Aufschlag von etwa 15 Prozent.

## Warum das praktisch wichtig ist

Token sind die Recheneinheit für fast alles:

- **Abrechnung.** Anbieter rechnen pro Token ab, Ein- und Ausgabe getrennt und unterschiedlich teuer.
- **Grenzen.** Das Context Window wird in Token gemessen, nicht in Zeichen oder Seiten.
- **Geschwindigkeit.** Durchsatz wird in Token pro Sekunde angegeben.

Wer die Größe eines Textes abschätzen will, sollte deshalb nicht Zeichen zählen und teilen, sondern messen. Anbieter stellen dafür Endpunkte bereit, die exakt zählen, statt zu raten.

<Callout type="achtung">
Ein verbreiteter Fehler ist, für die Schätzung einen fremden Tokenizer zu verwenden — etwa `tiktoken` für ein Modell, das gar nicht damit arbeitet. Das Ergebnis liegt je nach Sprache und Inhalt zweistellig daneben. Bei Code und nicht-englischem Text ist die Abweichung am größten.
</Callout>

## Was ein Token nicht ist

Ein Token ist keine Bedeutungseinheit. Die Zerlegung folgt der Statistik des Trainingskorpus, nicht der Grammatik. Deshalb passieren Dinge, die auf den ersten Blick seltsam wirken:

- Ein Leerzeichen gehört meistens zum **folgenden** Wort — `" Fenster"` ist ein Token, `"Fenster"` am Satzanfang ein anderes.
- Dieselbe Buchstabenfolge kann je nach Umgebung unterschiedlich zerlegt werden.
- Zahlen werden häufig in mehrere Token zerhackt, was ein Grund dafür ist, dass Modelle beim Rechnen stolpern.

Das erklärt auch den Klassiker, warum Modelle Buchstaben in einem Wort schlecht zählen können: Sie sehen die Buchstaben gar nicht einzeln, sondern nur die Token-Brocken.

<KeyTakeaway>
- Ein Token ist die kleinste Einheit, in der ein Modell Text wahrnimmt — eine Zahl aus einem festen Vokabular.
- Der Tokenizer gehört zum Modell und ist fix. Vom Betreiber hängt die nutzbare Kontextlänge ab, nicht die Tokenisierung.
- Die Regel „Deutsch kostet zwei- bis dreimal so viel" stammt aus der Zeit älterer Tokenizer. Heute liegt der Aufschlag bei etwa 15 Prozent — bei Komposita mehr.
- Zum Abschätzen messen statt rechnen — und nie mit dem Tokenizer eines anderen Modells.
</KeyTakeaway>
