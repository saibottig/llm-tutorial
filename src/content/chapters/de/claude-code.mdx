Ein Modell allein ist eine Funktion: Text rein, Text raus. Alles, was daraus ein Werkzeug macht, heißt **Harness** — und Claude Code ist genau das: ein Harness im Terminal, per Plugin auch in IntelliJ und VS Code. Zwei Kolleginnen mit demselben Modell bekommen unterschiedliche Ergebnisse, weil ihre Einrichtung unterschiedlich ist — nicht ihr Modell.

## Was Claude Code pro Anfrage übernimmt

| Aufgabe | Konkret | Kapitel |
| --- | --- | --- |
| Context zusammenstellen | CLAUDE.md, relevante Dateien, Verlauf | [Projekt-Setup](../setup/) |
| Tool-Schleife fahren | Dateien lesen/editieren, `./gradlew test`, Fehler behandeln | [Tool Use](../tool-use/) |
| Context verwalten | rechtzeitig komprimieren statt an der Wand abbrechen | [Context Window](../context-window/) |
| Rechte durchsetzen | was ohne Rückfrage läuft, was Bestätigung braucht | [Projekt-Setup](../setup/) |
| Caching optimieren | Aufbau so anordnen, dass der Cache greift | [Prompt Caching](../prompt-caching/) |
| Zustand halten | Sitzungen, Dateizustände, Rückgängigmachen | — |

<Callout type="merke">
Bei anspruchsvollen Aufgaben macht der Unterschied zwischen gut und schlecht eingerichtetem Claude Code oft mehr aus als der zwischen zwei Modellgenerationen. Die Einrichtung ist der Hebel, nicht das Beiwerk.
</Callout>

## Terminal und IDE: ein Werkzeug

Claude Code startet im Projektverzeichnis und arbeitet mit dessen Dateien und Befehlen. Die IDE-Integrationen setzen auf dasselbe Werkzeug auf — Diffs im Editor, geöffnete Datei als Kontext. Sitzungen, Permissions, CLAUDE.md: alles identisch. Was man im Terminal lernt, gilt in der IDE.

`/remote-control` erweitert dieselbe Sitzung auf ein anderes Gerät: Ein langer
Lauf, am Schreibtisch gestartet, lässt sich vom Telefon aus verfolgen und
beantworten. Die Sitzung wandert nicht — sie läuft weiter, wo sie gestartet ist,
und du bist nur derjenige, der freigibt.

## Enterprise-Betrieb: drei Konsequenzen

1. **Richtlinien sind vorkonfiguriert.** Erlaubte Befehle, freigegebene MCP-Server, Datenflüsse — teils zentral festgelegt. Wenn etwas nicht geht: meist Absicht, keine Fehlfunktion.
2. **Kosten sind ein Teamthema.** Abrechnung über das Unternehmen senkt die Hemmschwelle — und macht bewussten Umgang wichtiger → [Kostenbewusst arbeiten](../cost/).
3. **Erfahrungen sind teilbar.** CLAUDE.md, Skills, Abläufe wandern ins Repo statt in private Notizen → [Teil 4](../unit-tests/).

<Callout type="praxis">
Verhält sich Claude Code seltsam, lautet die erste Frage nicht „Welches Modell?", sondern „Was stand im Context?" — `/context` zeigt es. Die Antwort ist fast immer: etwas Veraltetes, etwas Fehlendes oder zu viel Irrelevantes.
</Callout>

<KeyTakeaway>
- Claude Code ist ein Harness: Context, Tool-Schleife, Compaction, Rechte, Caching — pro Anfrage.
- Die Qualität der Einrichtung schlägt bei schwierigen Aufgaben die Modellwahl.
- Terminal und IDE sind dasselbe Werkzeug — Wissen überträgt sich eins zu eins.
- Enterprise heißt: Richtlinien vorkonfiguriert, Kosten Teamthema, Einrichtung teilbar.
- Erste Diagnose bei seltsamem Verhalten: `/context`, nicht das Modell.
</KeyTakeaway>
