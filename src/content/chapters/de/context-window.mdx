Das **Context Window** ist das Fassungsvermögen: die maximale Tokenzahl pro Anfrage, inklusive der Antwort, die das Modell noch erzeugen wird. Nicht zu verwechseln mit [Context](../context/) — das ist der *Inhalt*, das Window die *Kapazität*. Aktuelle Modelle: 200k bis 1M Token.

## Wenn es voll wird

<Terminal script="context-window" locale="de" variant="inline" />

Drei mögliche Reaktionen beim Überlauf:

| Reaktion | Verhalten | Bewertung |
| --- | --- | --- |
| Fehler | Anfrage wird abgelehnt | ehrlich, aber unbrauchbar |
| Abschneiden | älteste Nachrichten fallen weg | Modell „vergisst" schlagartig den Anfang |
| Compaction | alte Runden werden zusammengefasst | am besten, aber verlustbehaftet |

Claude Code komprimiert automatisch vor der Wand. Die Griffe dazu:

- `/context` — zeigt, was die Sitzung gerade belegt
- `/compact` — Schnitt bewusst setzen, idealerweise nach einem abgeschlossenen Arbeitsschritt
- `/clear` — Neustart zwischen unabhängigen Aufgaben; eine Sitzung pro Aufgabe ist die gesunde Grundeinstellung

## Qualität sinkt vor der Kapazitätsgrenze

<Callout type="korrektur">
Ein 1M-Fenster heißt nicht, dass man 1M Token *nutzen sollte*. Ein präzise zusammengestellter Context von 20.000 Token schlägt regelmäßig einen unsortierten von 500.000. Zwei Effekte:

- **Lost in the Middle:** Modelle finden Informationen am Anfang und Ende zuverlässig, in der Mitte messbar schlechter.
- **Context Rot:** Fehlversuche, verworfene Ansätze und überholte Dateistände bleiben im Verlauf — und das Modell hält sie für gültigen Stand. Nicht nutzlos, sondern aktiv irreführend.
</Callout>

## Konsequenzen

- **Relevanz schlägt Vollständigkeit** — gezielt drei passende Dateien statt des halben Repositories.
- **Wichtiges an den Rand** — was unbedingt beachtet werden muss, gehört an Anfang oder Ende.
- **Lange Sitzungen brauchen Schnitte** — `/clear` mit sauberer Neuformulierung schlägt endloses Weiterschleppen.

<KeyTakeaway>
- Das Context Window ist die Obergrenze in Token, inklusive der zu erzeugenden Antwort.
- Claude Code komprimiert automatisch; `/context`, `/compact` und `/clear` sind die manuellen Griffe.
- Die nutzbare Qualität sinkt lange vor der Grenze: Mitte wird schlechter beachtet, alter Ballast führt aktiv irre.
- Ein großes Fenster ist eine Reserve, keine Einladung, es zu füllen.
</KeyTakeaway>
