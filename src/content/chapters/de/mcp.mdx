Das **Model Context Protocol** (MCP) ist ein offener Standard für die Anbindung von Modellen an bestehende Software — bei uns der Weg, auf dem Claude Code Jira, Confluence und Bitbucket erreicht. Statt jede Kombination aus Anwendung und System einzeln zu verdrahten (3 × 4 = 12 Integrationen), stellt ein Anbieter einen MCP-Server bereit, den jede MCP-fähige Anwendung nutzen kann (3 + 4 = 7 Bausteine).

Für unseren Stack: Atlassian betreibt einen offiziellen Remote-Server für die Cloud-Produkte (OAuth); für Data Center gibt es Community-Varianten. Den Alltagsnutzen zeigt [Ticket zu Pull Request](../atlassian/).

<Deep title="Was ein MCP-Server anbietet">
| Art | Was es ist |
| --- | --- |
| **Tools** | Funktionen, die das Modell aufrufen kann — der Hauptfall |
| **Resources** | Daten, die als Context bereitgestellt werden |
| **Prompts** | Vorlagen für wiederkehrende Aufgaben |

Technisch ist alles gewöhnlicher [Tool Use](../tool-use/); MCP standardisiert Entdeckung, Authentifizierung und Transport. Das Modell weiß von MCP nichts — es sieht nur Tool-Definitionen.
</Deep>

## Der Preis: Tool-Definitionen bei jeder Anfrage

Ein Jira-Server bringt gut zwei Dutzend Tools mit, jedes mit Beschreibung und Schema — präsent bei jedem Aufruf, auch wenn man nur einen Kommentar liest.

<McpCost locale="de" />

Alle Server an: fünfstelliger Verbrauch, bevor ein Wort der eigentlichen Aufgabe im Context steht — bei jeder Anfrage der Sitzung. Drei Folgen:

| Folge | Wirkung |
| --- | --- |
| Kosten | fester Grundbetrag pro Anfrage |
| Platz | fehlt für den eigentlichen Inhalt |
| **Trefferquote** | mehr ähnliche Tools → mehr Fehlgriffe. Der meistunterschätzte Effekt. |

<Callout type="achtung">
„Context Window Pollution" ist primär ein Qualitätsproblem, kein Kostenproblem: Ein Modell mit sechzig verfügbaren Tools entscheidet schlechter als eines mit acht passenden — auch wenn alle sechzig hineinpassen würden.
</Callout>

## Gegenmaßnahmen

1. **Nur nötige Server aktivieren.** Unspektakulär, am wirksamsten: Wer eine Angular-Komponente testet, braucht weder Jira- noch Postgres-Server im Context.
2. **Tool Search / Deferred Loading.** Definitionen werden als nachladbar markiert; im Context steht zunächst nur ein Suchwerkzeug, Schemas werden bei Bedarf geladen. Aus konstantem Grundverbrauch wird Sockel + tatsächlicher Bedarf — und der [Cache](../prompt-caching/) bleibt erhalten.

<Callout type="praxis">
Greift ein Agent auffällig oft daneben: erst die Zahl der aktiven Tools prüfen, dann am Prompt feilen. Die Hälfte abschalten wirkt oft stärker als jede Umformulierung.
</Callout>

## Abgrenzung

MCP ist ein **Anbindungsprotokoll** — Transport, Auth, Entdeckung. Es liefert kein Vorgehenswissen; dafür gibt es [Skills](../skills/), und die Gegenüberstellung im nächsten Kapitel ist wichtiger, als sie wirkt.

<KeyTakeaway>
- MCP standardisiert die Anbindung externer Systeme — bei uns: Jira, Confluence, Bitbucket.
- Tool-Definitionen liegen bei jeder Anfrage im Context: kostet Geld, Platz und vor allem Trefferquote.
- Wirksamste Maßnahme: nur die tatsächlich benötigten Server aktivieren; Tool Search entschärft große Sammlungen.
- MCP liefert Zugriff, keine Anleitung — das ist die Aufgabe von Skills.
</KeyTakeaway>
