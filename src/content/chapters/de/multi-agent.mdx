In Claude Code heißt Multi-Agent: Die Hauptsitzung startet für eine Teilaufgabe einen **Sub-Agenten** mit frischem Context — etwa „durchsuche das Monorepo nach allen Verwendungen dieser Schnittstelle". Das Muster dahinter:

```
                    ┌──────────────┐
                    │ Orchestrator │
                    └──────┬───────┘
              ┌────────────┼────────────┐
              ▼            ▼            ▼
         ┌────────┐   ┌────────┐   ┌────────┐
         │ Agent  │   │ Agent  │   │ Agent  │
         │ Suche  │   │ Code   │   │ Tests  │
         └────────┘   └────────┘   └────────┘
```

Der offensichtliche Vorteil ist **Parallelisierung**. Der wichtigere wird meist übersehen:

<Callout type="korrektur">
„Multi-Agent = mehr Context Pollution, weil jeder Agent alles wissen muss" — so nicht richtig. Sub-Agenten sind primär **Context-Isolation**: Der Sub-Agent liest zwanzig Dateien, verfolgt drei Sackgassen, produziert 50.000 Token Rohmaterial — und gibt **800 Token Zusammenfassung** zurück. Alles andere bleibt in seinem Context.

Der Trade-off lautet: **mehr Tokens insgesamt, weniger Pollution im Hauptthread.** Und weil der Hauptthread die Gesamtqualität bestimmt, ist das oft ein guter Tausch.
</Callout>

## Kosten und Schutz

**Kosten:** deutlich über einem einzelnen Agenten — je nach Zuschnitt von knapper Verdopplung bis Zehnfachem. Es ist eine Größenordnung, keine Randnotiz; den eigenen Fall messen statt fremde Zahlen übernehmen.

**Häufigster Ausfall: Schleifen.** Orchestrator fragt nach, Sub-Agent liefert Unbefriedigendes, Orchestrator fragt erneut — bis Budget oder Geduld aufgebraucht sind. Schutzmaßnahmen von Anfang an einbauen:

| Maßnahme | Regel |
| --- | --- |
| Iterationslimit | harte Obergrenze pro Agent — wirksamste Einzelmaßnahme |
| Token-Budget | Obergrenze pro Aufgabe, nicht pro Aufruf |
| Tiefenbegrenzung | Sub-Agenten starten keine eigenen Sub-Agenten |
| Fortschrittsprüfung | zwei Runden ohne Neues → abbrechen |
| Zeitlimit | Wanduhrzeit als Reißleine |

Wo es sich **nicht** lohnt: bei abhängigen Schritten (braucht Schritt 2 das
Ergebnis von Schritt 1, kauft der Aufschlag nichts) und bei allem, was ein
einzelner Agent ohnehin schafft.

Verwandt, aber keine Orchestrierung: mehrere Claude-Code-Sitzungen in getrennten **Git-Worktrees**, jede auf eigenem Branch — die Koordination macht der Mensch, die Einsicht ist dieselbe: getrennte Aufgaben, getrennte Contexte.

## Rollen, für die sich ein Sub-Agent lohnt

Der Wert eines Sub-Agenten ist sein eigenes Fenster. Gib ihm also Arbeit, deren
*Rohmaterial* du nicht zurückhaben willst — und eine Rolle, die sich in einem
Absatz beantworten lässt.

| Rolle | Auftrag | Zurück kommt |
| --- | --- | --- |
| Kundschafter | „Wo wird X im Monorepo überall benutzt?" | die Stellen, nicht die Dateien |
| Advocatus Diaboli | „Argumentiere gegen diesen Plan; nenne, was bricht" | die Einwände, die standhalten |
| Prüfer | „Gleich diesen Diff gegen das Ticket ab" | passt, oder die Abweichung |

Unterschätzt wird der Advocatus Diaboli: Ein zweiter Agent mit frischem Context
und dem Auftrag zu widersprechen findet, was der Agent nicht findet, der den Plan
geschrieben hat — weil er ihn nicht verteidigt.

<Callout type="achtung">
Ein widersprechender Sub-Agent ist ein LLM-Judge, mit den Eigenheiten aus dem
Kapitel [Evals](../evals/) — Positionseffekte, schlechte Kalibrierung. Er liefert
lesenswerte Einwände; er entscheidet sie nicht.
</Callout>

<Deep title="Ein anderes Modell je Sub-Agent">
Sub-Agenten können ein kleineres Modell fahren als der Hauptthread — Planung auf
dem teuren, mechanische Arbeit auf dem günstigen, bei Faktor fünf zwischen
größter und kleinster Klasse → [Kostenbewusst arbeiten](../cost/).

Der Fehler ist, das über einen Modellwechsel der *Hauptsitzung* mitten in der
Aufgabe zu tun. Caches gehören zu genau einem Modell, der Wechsel wirft den
gesamten Sitzungs-Präfix weg — voller Preis in jeder folgenden Runde, um in
einer einen Bruchteil zu sparen. Erst die Delegation macht die Aufteilung
bezahlbar: Das günstige Modell läuft im eigenen Fenster des Sub-Agenten, der
Cache des Hauptthreads bleibt heil.
</Deep>

<KeyTakeaway>
- Sub-Agenten bringen Parallelisierung — und, wichtiger, Context-Isolation: Rohmaterial bleibt draußen.
- Trade-off: mehr Tokens insgesamt, weniger Pollution im Hauptthread — oft ein guter Tausch.
- Mehrkosten sind eine Größenordnung und stark zuschnittabhängig: messen statt übernehmen.
- Schleifen mit Iterationslimit, Budget und Tiefenbegrenzung von Anfang an verhindern.
- Sub-Agenten eine enge Rolle geben — Kundschafter, Advocatus Diaboli, Prüfer — und ein günstigeres Modell; nie das Modell der Hauptsitzung wechseln, um zu sparen.
</KeyTakeaway>
