Der Arbeitstag beginnt mit einem Jira-Ticket und endet mit einem Bitbucket-PR — über [MCP](../mcp/) erreicht Claude Code alle Stationen dazwischen. Cloud: offizieller Atlassian-Remote-Server (einmal OAuth). Data Center: Community-Server per `claude mcp add`. Was freigeschaltet ist, regelt die [zentrale Konfiguration](../claude-code/).

## Der Durchstich in fünf Schritten

1. **Ticket statt Nacherzählung.** „Setz TOS-4711 um" reicht: Claude liest Titel, Beschreibung, Akzeptanzkriterien und die Kommentar-Diskussion — mehr Kontext, als jede mündliche Zusammenfassung transportiert.
2. **Plan Mode vor dem ersten Edit.** Read-only: Claude liest Ticket, Code, Module und legt einen Plan vor. Ein verworfener Plan kostet einen Bruchteil einer verworfenen Implementierung → [Kostenbewusst arbeiten](../cost/). Ab einer Handvoll betroffener Dateien: immer.
3. **Umsetzung mit Verifikation.** Implementierung und Tests, Claude führt Build und Tests selbst aus → [Unit-Tests](../unit-tests/).
4. **Branch und PR.** `feature/TOS-4711-…` nach Team-Schema; die PR-Beschreibung entsteht aus Diff + Ticket.
5. **Doku mitziehen** — betroffene Confluence-Seite als Vorschlag aktualisieren, nicht als stiller Automatismus.

<Callout type="praxis">
Der unterschätzte Schritt ist Nr. 4: Eine gute PR-Beschreibung braucht genau das, was ohnehin im Context liegt — Diff und Ticket. Kostet nichts extra, Reviewer merken den Unterschied sofort.
</Callout>

## Die Grenze: lesen breit, schreiben schmal

| Zugriff | Risiko | Empfehlung |
| --- | --- | --- |
| Tickets/Seiten lesen | gering | freigeben |
| PR anlegen | mittel, sichtbar | vor dem Absenden anzeigen |
| Tickets kommentieren, Seiten ändern | nach außen sichtbar | einzeln bestätigen |

Ein falscher Kommentar am falschen Ticket ist öffentlich; eine falsch editierte Datei nicht.

<Callout type="achtung">
Alles über MCP Gelesene ist fremder Input: Ticket-Texte, Kommentare und Confluence-Seiten können Text enthalten, der wie eine Anweisung aussieht — und Claude kann ihn als Auftrag interpretieren. Warum das strukturell schwer verhinderbar ist: [Prompt Injection](../prompt-injection/).
</Callout>

<KeyTakeaway>
- Über Atlassian-MCP erreicht Claude Code Jira, Confluence und Bitbucket — vom Ticket bis zum PR.
- Ticket-Verweis schlägt Nacherzählung: Beschreibung, Akzeptanzkriterien, Kommentare kommen mit.
- Plan Mode vor der Umsetzung — ein verworfener Plan ist billig, eine verworfene Implementierung nicht.
- PR-Beschreibung aus Diff + Ticket generieren lassen: der unterschätzte Gewinn.
- Lesen breit, schreiben schmal — und alles Gelesene ist fremder Input.
</KeyTakeaway>
