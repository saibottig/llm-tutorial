After the first weeks with [unit tests](../unit-tests/) the question arrives: what else? The worst answer is "everything" — it produces disappointing attempts at unsuitable tasks. Better: three questions before every attempt.

## The grid

| # | Question | What is behind it |
| --- | --- | --- |
| 1 | **Does the task repeat** — or is it big enough? | setup effort must spread across runs |
| 2 | **Is the result checkable?** | without a verification path, good and good-looking are indistinguishable → [hallucinations](../hallucinations/) |
| 3 | **Is the context obtainable?** | does the knowledge live in code/ticket/docs — or in a colleague's head? |

<Callout type="merke">
Two of three "yes" → worth a try. Three times "no" → leave it: the task offers the tool nothing to grip; the model is not the problem.
</Callout>

## Candidates that pass

| Use case | Why it works |
| --- | --- |
| Closing test gaps | checkable, recurring, context in the repo |
| Explaining legacy code | Claude skims faster than any human; checkable by reading the cited places |
| Stack trace / log analysis | trace + code in, hypothesis out; verifiable against behaviour |
| Mechanical migrations | deprecated APIs, version bumps, one pattern across 30 files; checkable via build/tests |
| Confluence docs from code | the interface page two releases behind; review by the domain owner |
| Pre-review pass | check your own diff before human review; raises the baseline |

## Anti-candidates

| Case | Where it fails |
| --- | --- |
| Architecture decisions | no checkable result; the decisive context (history, politics) is written down nowhere |
| Code nobody can check | the verification path is missing by definition |
| Highly specific optimisation logic (e.g. crane scheduling) | years of terminal experience are not obtainable; subtle errors go unnoticed |
| One-off with high context cost | gathering context takes longer than the task |

## From single case to team workflow

Grid passed + proven three times → capture as a [skill](../skills/) or slash command ([Agentic Workflows](../agentic-workflows/)). Then the team benefits, not just the discoverer.

<Callout type="praxis">
Surprisingly effective during rollout: a Confluence page listing every discovered case in two sentences plus the prompt — **including the failures**. It quickly becomes the team's most-read page and saves everyone the same detours.
</Callout>

<KeyTakeaway>
- Three questions before every attempt: does it repeat? checkable? context obtainable?
- Good candidates: test gaps, explaining legacy, log analysis, migrations, docs from code, pre-review.
- Anti-candidates: architecture questions, the uncheckable, unobtainable domain context.
- Capture what works as a skill/slash command — team benefit over individual knowledge.
- Document cases and failures visibly: it speeds up everyone's onboarding.
</KeyTakeaway>
