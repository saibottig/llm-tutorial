The **context window** is the capacity: the maximum token count per request, including the response the model has yet to produce. Not to be confused with [context](../context/) — that is the *content*, the window is the *capacity*. Current models: 200k to 1M tokens.

## When it fills up

<Terminal script="context-window" locale="en" variant="inline" />

Three possible responses to overflow:

| Response | Behaviour | Verdict |
| --- | --- | --- |
| Error | request rejected | honest, but useless |
| Truncation | oldest messages dropped | model abruptly "forgets" the beginning |
| Compaction | old turns summarised | best, but lossy |

Claude Code compacts automatically before the wall. The controls:

- `/context` — shows what the session currently occupies
- `/compact` — place the cut deliberately, ideally after a finished unit of work
- `/clear` — restart between independent tasks; one session per task is the healthy default

## Write it down before the window forgets it

Compaction summarises history, files and output. It cannot summarise what was
never in the window — and the filesystem is not in the window.

| File | Written | Bought you |
| --- | --- | --- |
| `plan.md` | before the first edit, from plan mode | the plan survives compaction; re-reading it costs one file read, not a re-derivation |
| `decisions.md` | when a choice is made | the *why* survives, so the next session does not relitigate it |

Both are ordinary files in the repo, so a fresh session starts from a written
brief instead of from memory — the same move as a [skill](../skills/).

Ending a long session: have Claude write down what was done, what is open, and
what the next session needs to know. A repo-local slash command makes it one
keystroke → [Agentic Workflows](../agentic-workflows/).
</Callout>

## Quality drops before the capacity limit

<Callout type="korrektur">
A 1M window does not mean you *should* use 1M tokens. A carefully assembled context of 20,000 tokens regularly beats an unsorted one of 500,000. Two effects:

- **Lost in the middle:** models retrieve information reliably at the beginning and end, measurably worse in the middle.
- **Context rot:** failed attempts, abandoned approaches and superseded file states stay in the history — and the model takes them for current. Not useless but actively misleading.
</Callout>

## Consequences

- **Important things go to the edges** — whatever must be honoured belongs at the start or the end.
- **Long sessions need cuts** — `/clear` with a written brief beats dragging on indefinitely.

<KeyTakeaway>
- The context window is the ceiling in tokens, including the response still to be generated.
- Claude Code compacts automatically; `/context`, `/compact` and `/clear` are the manual controls.
- Usable quality drops long before the limit: the middle gets less attention, old ballast actively misleads.
- A large window is a reserve, not an invitation to fill it.
- What must survive compaction belongs on disk: `plan.md`, `decisions.md`, a written handoff.
</KeyTakeaway>
