A model reads neither letters nor words but **tokens**: numbers from a fixed vocabulary of 100,000–200,000 entries. Everything in a Claude Code session — CLAUDE.md, Java classes, stack traces, Jira tickets — is measured, counted and billed in tokens.

Rough anchors:

| Text | Token cost |
| --- | --- |
| common short word (`window`) | 1 token |
| long compound (`Rechtsschutzversicherung`) | several tokens |
| English | ~5 characters per token |
| German | ~15 % more tokens than English |
| code, logs, JSON | noticeably more than prose of the same length |

## The tokenizer belongs to the model

The same text always produces exactly the same token sequence on the same model — no matter where it runs or who operates it.

<Callout type="korrektur">
"The token count depends on the server" — no. Tokenization is part of the model and fixed. What depends on the operator is the **usable context length**: a model may technically handle 1M tokens but be served capped at 200k.

Also outdated: "German costs 2–3×". That held for older tokenizers. Measured with current ones: **+16 %** (`o200k_base`) versus **+53 %** (`cl100k_base`).
</Callout>

## Practical rules

- **Measure, don't estimate.** Providers expose counting endpoints; in Claude Code, `/context` shows the session's consumption.
- **Never estimate with a foreign tokenizer** (e.g. `tiktoken` for a non-OpenAI model): off by double digits depending on content, worst for code and non-English text.
- **Billing, limits, speed** — all measured in tokens: prices per token (input/output separately), context window in tokens, throughput in tokens/s.

<Deep title="Why models cannot count letters">
A token is not a unit of meaning — the split follows the statistics of the training corpus, not grammar:

- A space usually belongs to the **following** word: `" window"` and `"window"` at sentence start are different tokens.
- The same letter sequence can be split differently depending on its surroundings.
- Numbers get chopped into pieces — one reason models stumble over arithmetic.

The model never sees individual letters, only token chunks. That is why it fails at counting letters — it counts in a unit it cannot see.
</Deep>

<KeyTakeaway>
- A token is the smallest unit in which a model perceives text — everything is measured and billed in it.
- The tokenizer is part of the model and fixed; the operator only sets the usable context length.
- German costs ~15 % more than English today, not 2–3× — the old rule dates from older tokenizers.
- Measure rather than calculate, never with another model's tokenizer.
</KeyTakeaway>
