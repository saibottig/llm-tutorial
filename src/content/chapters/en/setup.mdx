JUnit 4 tests instead of JUnit 5, Maven instead of Gradle, classes in directories that do not exist — these are not model weaknesses but missing project context. The fix is one file: **`CLAUDE.md`** in the project directory, read at every session start.

## What belongs in it: three categories

| Category | Content | Example |
| --- | --- | --- |
| **Commands** | build, test, lint | `./gradlew test --tests "…"` |
| **Conventions** | what Claude would otherwise guess | "AssertJ, not Hamcrest" |
| **Boundaries** | what is not touched | `src/generated/**` |

For one of our services it looks like this:

```markdown
# berth-planning-service

Spring Boot 3 / Java 21, Gradle. Part of the vessel domain.

## Commands
- Build: ./gradlew build
- Single test: ./gradlew test --tests "BerthAllocationServiceTest"
- Static analysis: ./gradlew spotlessCheck

## Conventions
- Tests: JUnit 5 + Mockito + AssertJ. Slices (@WebMvcTest, @DataJpaTest)
  over @SpringBootTest where possible.
- DTOs are records. MapStruct for mapping, no manual copying.
- Timestamps always Instant; timezone logic only in the REST layer.

## Do not touch
- src/generated/** (generated from OpenAPI)
- Flyway migrations — new files only, never edit
```

<Callout type="merke">
The CLAUDE.md travels with **every request** as part of the [context](../context/) — every line costs tokens on every turn. Constitution, not handbook: rare material belongs in a [skill](../skills/) or in Confluence.
</Callout>

## Shape per repo type

- **Monorepo:** lean root file (build system, cross-cutting rules) + one per module with conventions of its own. Claude Code reads files along the path — module supplements root.
- **Microservices:** one file per repo. Maintain a shared core as a template (e.g. in Confluence) + the three or four service-specific lines.
- **Angular workspace:** test commands (`ng test`, Jest or Karma), component conventions (standalone? signals?), where shared UI building blocks live.

## Permissions: tier instead of clicking away

In `.claude/settings.json`, checked into the repo — then it applies to the whole team:

| Tier | Example |
| --- | --- |
| without asking | `./gradlew test`, `ng test`, `git diff` |
| with confirmation | `git push` |
| blocked | destructive commands |

Central company policies sit above; project-side you can only tighten, never loosen.

<Callout type="achtung">
No credentials, tokens or internal hostnames in the CLAUDE.md — it is part of every request and lives in the repo.
</Callout>

<Callout type="praxis">
Extension trigger: typing the same correction for the second time. Written into the file once, it applies to every future session — in chat, exactly once.
</Callout>

<KeyTakeaway>
- CLAUDE.md = commands + conventions + boundaries; it replaces guessing.
- It costs tokens on every request: keep it lean, move rare material out.
- Monorepo: root + module files; microservices: shared core + specifics.
- Permissions in settings.json in the repo — test runs free, push with confirmation, destructive blocked.
- A repeated correction = signal for the file; secrets never go in.
</KeyTakeaway>
