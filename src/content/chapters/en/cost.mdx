Billing is per token, input and output separately. The surprising truth behind it: **in Claude Code sessions, input dominates at 80–95 % of cost** — although output is about five times more expensive per token. The reason is in the [Context](../context/) chapter: every turn resends the entire history; turn 30 pays for the beginning for the thirtieth time.

<Deep title="Price structure of the model classes">
Prices per 1M tokens, orders of magnitude (they change; the ratios persist):

| Model class | Input | Output |
| --- | --- | --- |
| large, for hard tasks | ~$5 | ~$25 |
| medium, for most of the load | ~$3 | ~$15 |
| small, for simple tasks | ~$1 | ~$5 |

Two ratios matter, and both are roughly a factor of five: output against input **within** a class, and the largest class against the smallest. Between neighbouring classes it is less — which is why the step down is often free of consequence. Enterprise operation means no private bill, but the same mechanics sit behind the usage quotas.
</Deep>

<Callout type="merke">
Saving means working the input side — the context. Cost discipline and the context hygiene from the [Context Window](../context-window/) chapter are the same exercise — lean context is cheaper *and* better.
</Callout>

## The four mechanical levers

| Lever | Effect | How |
| --- | --- | --- |
| [Prompt caching](../prompt-caching/) | up to −90 % on input | automatic — just don't break it (MCP/CLAUDE.md mid-session) |
| Model choice per task | up to factor 5, largest against smallest | `/model`; commit messages and renames need no top model |
| Lean context | linear per token saved | [MCP servers](../mcp/) off, point at files, research in [sub-agents](../multi-agent/) |
| Batch processing | −50 % | asynchronous processing for anything that can wait |

## The five daily habits

1. **One session per task.** `/clear` between independent tasks — otherwise the old history rides along as paid-for, actively distracting ballast. The cheapest single measure.
2. **Plan mode before large changes.** Discarded plan: a few thousand tokens. Discarded implementation plus failed attempts: a multiple, plus a flooded history.
3. **`!` prefix for commands that need no model.** The command runs directly, only its output lands in context — no model round trip.
4. **`/compact` at section boundaries** instead of automatically at the wall — the summary of a finished state is better.
5. **Precise tasks.** "Tests for the changed methods in this diff" instead of "take care of tests" — every exploration round costs.

<Callout type="praxis">
Before any optimisation: look at `/context`. Two unused MCP servers and the history of three finished tasks are a bigger lever than any prompt wording.
</Callout>

## What achieves little

- ✗ **Trimming the prompt** — saving 200 tokens against a 20,000-token history is symbolic politics
- ✗ **Keeping output short** — with agents it is rarely the cost driver
- ✗ **Cheaper model despite a hard task** — three attempts save nothing

## Extra rules for automation

As soon as Claude Code runs headless in a pipeline ([Agentic Workflows](../agentic-workflows/)):

- **Measure per operation, not per request** — one pipeline run is easily fifty calls.
- **Plan for the worst case** — costs are right-skewed: most operations cheap, a few explode.
- **Hard ceilings per operation** — without a limit, a loop is not a glitch but a bill → [Multi-Agent](../multi-agent/).

<KeyTakeaway>
- Input dominates at 80–95 % because the history travels every turn — saving means saving context.
- Mechanical levers: caching, model choice per task, lean context, batch processing.
- Habits: `/clear` per task, plan mode, `!` prefix, `/compact` at boundaries, precise tasks.
- Look at `/context` first, then optimise.
- Automation needs per-operation measurement and hard ceilings.
</KeyTakeaway>
