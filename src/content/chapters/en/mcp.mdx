The **Model Context Protocol** (MCP) is an open standard for connecting models to existing software — for us, the route by which Claude Code reaches Jira, Confluence and Bitbucket. Instead of wiring every application-system combination individually (3 × 4 = 12 integrations), a provider ships an MCP server any MCP-capable application can use (3 + 4 = 7 building blocks).

For our stack: Atlassian runs an official remote server for the cloud products (OAuth); community variants exist for Data Center. The day-to-day payoff is shown in [Ticket to Pull Request](../atlassian/).

<Deep title="What an MCP server offers">
| Kind | What it is |
| --- | --- |
| **Tools** | functions the model can call — the main case |
| **Resources** | data provided as context |
| **Prompts** | templates for recurring tasks |

Technically it is all ordinary [tool use](../tool-use/); MCP standardises discovery, authentication and transport. The model knows nothing of MCP — it only sees tool definitions.
</Deep>

## The price: tool definitions on every request

A Jira server brings a good two dozen tools, each with description and schema — present on every call, even when all you read is one comment.

<Terminal script="mcp" locale="en" variant="inline" servers />

All servers on: five-figure consumption before a single word of the actual task is in context — on every request of the session. Three consequences:

| Consequence | Effect |
| --- | --- |
| Cost | fixed base charge per request |
| Room | missing for the actual content |
| **Hit rate** | more similar tools → more wrong picks. The most underestimated effect. |

<Callout type="achtung">
"Context window pollution" is primarily a quality problem, not a cost problem: a model with sixty available tools decides worse than one with eight fitting ones — even if all sixty would fit.
</Callout>

## Countermeasures

1. **Enable only needed servers.** Unglamorous, most effective: someone testing an Angular component needs neither the Jira nor the Postgres server in context.
2. **Tool search / deferred loading.** Definitions are marked loadable on demand; initially only a search tool sits in the context, schemas load as needed. Constant baseline becomes base + actual usage — and the [cache](../prompt-caching/) survives.

<Callout type="praxis">
If an agent picks wrong noticeably often: check the number of active tools before polishing the prompt. Switching half off frequently beats any rewording.
</Callout>

## What MCP is not

MCP is a **connection protocol** — transport, auth, discovery. It supplies no procedural knowledge; that is what [skills](../skills/) are for, and the comparison in the next chapter matters more than it appears.

<KeyTakeaway>
- MCP standardises connections to external systems — for us: Jira, Confluence, Bitbucket.
- Tool definitions sit in the context on every request: costing money, room and above all hit rate.
- Most effective measure: enable only the servers actually needed; tool search defuses large collections.
- MCP supplies access, not instructions — that is the job of skills.
</KeyTakeaway>
