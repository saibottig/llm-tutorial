A model on its own is a function: text in, text out. Everything that turns it into a tool is called a **harness** — and Claude Code is exactly that: a harness in the terminal, via plugin also in IntelliJ and VS Code. Two colleagues with the same model get different results because their setup differs — not their model.

## What Claude Code handles per request

| Job | Concretely | Chapter |
| --- | --- | --- |
| Assemble context | CLAUDE.md, relevant files, history | [Project Setup](../setup/) |
| Run the tool loop | read/edit files, `./gradlew test`, handle errors | [Tool Use](../tool-use/) |
| Manage context | compact in time instead of failing at the wall | [Context Window](../context-window/) |
| Enforce permissions | what runs without asking, what needs confirmation | [Project Setup](../setup/) |
| Optimise caching | arrange the request so the cache hits | [Prompt Caching](../prompt-caching/) |
| Keep state | sessions, file states, undo | — |

<Callout type="merke">
On demanding tasks, the difference between well and poorly configured Claude Code often outweighs the difference between two model generations. The setup is the lever, not a side note.
</Callout>

## Terminal and IDE: one tool

Claude Code starts in the project directory and works with its files and commands. The IDE integrations build on the same tool — diffs in the editor, the open file as context. Sessions, permissions, CLAUDE.md: all identical. What you learn in the terminal applies in the IDE.

## Enterprise operation: three consequences

1. **Policies come preconfigured.** Allowed commands, approved MCP servers, data flows — partly set centrally. If something does not work: usually intentional, not broken.
2. **Cost is a team topic.** Company billing lowers the barrier — and makes deliberate usage more important → [Working Cost-Consciously](../cost/).
3. **Experience is shareable.** CLAUDE.md, skills, workflows go into the repo instead of private notes → [part 4](../unit-tests/).

<Callout type="praxis">
When Claude Code behaves strangely, the first question is not "which model?" but "what was in the context?" — `/context` shows it. The answer is almost always: something outdated, something missing, or too much that is irrelevant.
</Callout>

<KeyTakeaway>
- Claude Code is a harness: context, tool loop, compaction, permissions, caching — per request.
- Setup quality beats model choice on hard tasks.
- Terminal and IDE are the same tool — knowledge transfers one to one.
- Enterprise means: policies preconfigured, cost a team topic, setup shareable.
- First diagnosis for odd behaviour: `/context`, not the model.
</KeyTakeaway>
