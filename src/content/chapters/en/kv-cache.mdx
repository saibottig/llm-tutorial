The **KV cache** is the mechanism behind two everyday observations: why long contexts are expensive and why [prompt caching](../prompt-caching/) saves so much.

## Problem and solution in four sentences

For every new token the model looks back at all previous ones (attention) and would need their intermediate values — **keys and values** — recomputed each time. That would be quadratic effort: a thousand computations for token 1,000, a thousand and one for token 1,001. The rescue: keys and values of already-processed tokens **never change again**. So they are computed once and kept — quadratic becomes linear.

<Callout type="merke">
The KV cache is not an optimisation at the margins but the precondition for text generation being practical at all.
</Callout>

## The price: memory

Compute is saved, memory is paid — growing linearly with context length. For a 70B-class model with GQA, 16 bits per value, roughly **0.3 MB per token**:

| Context length | KV cache (70B model) | For comparison |
| --- | --- | --- |
| 8,000 tokens | ~2.5 GB | |
| 128,000 tokens | ~40 GB | ≈ the weights of that model served at 4 bits (~39 GB) |
| 1,000,000 tokens | ~305 GB | ≈ 8× those weights |

<Callout type="achtung">
This is why providers cap usable context length and sometimes surcharge long context: the limit is not the model but the memory for its cache — the operational decision from the [Tokens](../token/) chapter.
</Callout>

<Deep title="How operators shrink the cache">
Three techniques that show up in model descriptions:

- **Grouped-query attention (GQA):** several attention heads share keys/values — a factor of 4–8 smaller. Standard in current models; the table above already assumes it.
- **Quantised KV cache:** 8 instead of 16 bits per value — half the requirement, modest quality cost.
- **PagedAttention:** manage the cache in blocks like an operating system's virtual memory — less waste, shared prefixes across concurrent requests (popularised by vLLM).
</Deep>

<KeyTakeaway>
- The KV cache stores the intermediate values of processed tokens — quadratic effort becomes linear.
- The price is memory: at 128k context as much as the same model's 4-bit weights, at 1M eight times as much.
- The cache, not the model, is usually what caps usable context length.
- Kept across requests, the mechanism is called prompt caching — the largest cost lever.
</KeyTakeaway>
